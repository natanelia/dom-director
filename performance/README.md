# Measured synthetic workloads and lifecycle cleanup

Run `python3 tools/build_runtime.py`, install the pinned browser test dependencies and Chromium, then run `python3 performance/run.py`. This generates `performance-results/results.json`; the CI run retains that measurement artifact. No benchmark numbers are claimed before a successful measured run.

The fixture compares baseline host work, a direct CSS transform driven by the same pure visual sampler, and the full SDK. It uses 1,000 static elements, 10,000 static elements, and 1,000 elements with a host text update every fourth frame. Each combination has five warm-up runs and twenty measured runs of thirty real animation frames. A manually advanced presentation clock gives both camera implementations the same trajectory; actual requestAnimationFrame scheduling gives the host a real rendering opportunity between samples. The test verifies the final camera pose against the reference and rejects silent overlay fallback or a stopped player.

Raw per-frame synchronous CPU durations, frame intervals, setup time and geometry-read counts are retained. CPU measurements include the synthetic host update plus the direct/player callback, but exclude browser paint/raster work and work deferred to observer callbacks. Setup includes SDK surface preflight; it is reported separately. Run ordering is fixed and results are not evidence of causal speedups or universal frame rates. Headless CI hardware is not a physical phone or a production application.

The provisional gate is p95 synchronous SDK callback work below 3 ms on each workload. Static geometry must not be reread every frame; updating geometry has a bounded invalidation budget. A failed gate must be investigated rather than removed or relabeled as success. No layout or compositing guarantee is inferred from CPU time alone.

A separate 100-cycle check creates, loads, plays, seeks and destroys directors, including double destroy. It checks tracked resize/mutation observers, document/window/scene/viewport/font/visual-viewport/media-query listeners, scheduled callbacks, overlay nodes, restored inline styles and preserved host DOM identity. This is resource-lifecycle evidence, not a heap-snapshot proof that arbitrary host callbacks cannot retain memory. React Strict Mode and repeated mounts have their own actual React browser matrix.
